# 从测试开发到 Agent / 具身智能：38 周学习计划

> **定制对象**：测试开发工程师（Python 主要写测试脚本与自动化），每周稳定投入 **10 小时**
> **起点**：2026-10-19（周一）　**终点**：2027-07-11
> **总投入**：约 380 小时（38 周 × 10h）
> **依据**：[AgentGuide 开发工程师学习路线](https://github.com/adongwanai/AgentGuide/blob/main/docs/05-roadmaps/learning-roadmap-development.md) 与 [2026 Agent 求职通关路线](https://github.com/adongwanai/AgentGuide/blob/main/docs/05-roadmaps/agent-job-ready-roadmap-2026.md)，按你的时间与背景做了裁剪、重排和补强。

## 一、先把目标说清楚

你要的三个结果，按顺序解锁：

| # | 结果 | 时间点 | 判定标准 |
|:--|:--|:--|:--|
| 1 | **能自己造 Agent** | 2027-04 | 不用框架也能手写 Agent Loop；能做出带工具、记忆、评测、监控、部署的完整系统 |
| 2 | **能面 Agent 岗** | 2027-04 起投 | 2 个可运行、可评测、讲得清取舍的项目 + 量化指标 |
| 3 | **能进具身智能** | 2027-07 | 跑通 VLA 模型的仿真复现 + sim2real demo，读得懂论文、说得清架构 |

第 3 条我做了**降级处理**，原因见 1.2，请务必先看，避免 8 个月后目标错位。

### 1.1 你的背景是资产，不是短板

大部分人从"算法"挤进 Agent，但真正缺人的地方是：**把 Agent 的不确定性变成可度量、可回归、可定位的东西**。这恰好是测试开发的本职。

| 你已经在做的事 | Agent 团队里的对应能力 | 稀缺度 |
|:--|:--|:--|
| 用例设计与边界分析 | 评测集设计、rubric 制定、难度分层 | ★★★★★ |
| 自动化测试框架 | Agent Eval Harness、CI 回归流水线 | ★★★★★ |
| 稳定性 / 故障注入 | 工具失败、超时、幻觉、循环的鲁棒性测试 | ★★★★★ |
| 缺陷定位与日志分析 | Trace / Replay / 失败归因分类 | ★★★★☆ |
| 性能压测 | Token 成本、P99 延迟、吞吐 benchmark | ★★★★☆ |
| 接口测试 | 工具 schema 契约测试、MCP Server 测试 | ★★★★☆ |

**这条路线属于你、别人不容易抢**：同样做 Agent 项目，别人交一个"demo 好看"的仓库，你交一个"20 条 case、通过率 82%、失败分 5 类、改一版提升到 91%"的仓库。面试官信哪个，不用我说。

> 落地策略：**项目要做成"测试开发 × Agent"的交叉件**，而不是又一个 RAG 问答 demo。见第六章项目 2。

### 1.2 现实校准（重要，别跳过）

| 路线 | 典型岗位 | 你要补的 | 10h/周可行性 | 建议 |
|:--|:--|:--|:--|:--|
| **T1 Agent 应用开发** | Agent 应用工程师、LLM 应用后端 | 全栈 + Agent 工程 + 部署 | **高** | 主路线，2027-04 起投 |
| **T2 Agent 评测 / 质量** | Agent 评测工程师、AI 质量工程、大模型评测 | 评测方法论 + 一点统计 | **很高（你已有一半）** | 最快变现，2027-02 就可以试投 |
| **T3 具身智能算法** | VLA 算法工程师、机器人学习 | 数学 + 强化学习 + 机器人学 + 论文 | **低** | 不建议作为主攻 |
| **T3′ 具身智能工程** | 仿真工程、数据管线、算法落地、评测 | 仿真 + 数据 + 部署 | **中** | 现实可行的具身入口 |

直说：10h/周 × 14 周 = 140 小时，够你**跑通并讲清楚**，不够你**独立设计 VLA 算法**。所以 Phase B 的目标定为"复现 + 评测 + sim2real 打通"，定位是具身的**工程 / 仿真 / 数据 / 评测**角色，不是算法研究员。真要走算法岗，另需 12 个月以上全职或读研——这个判断你可以自己再验证，但别用计划表骗自己。

同时**别等学完再投**：2027-02 就可以开始投 T2 类岗位，用面试反馈反哺学习，比闭门造车快得多。

## 三、分阶段详细计划

### 阶段 0｜地基（W1–W2，10/19–11/01）

**目标**：不是学 Python 语法，而是把"能跑、能测、能部署"的工程骨架搭起来。你写测试脚本没问题，短板通常在**类型约束、异步、工程结构**。

| 周 | 日期 | 主线 | 周末交付（可验收） |
|:--|:--|:--|:--|
| W1 | 10/19–10/25 | `uv`/`pyproject` 项目管理、类型注解 + Pydantic、`async/await` + `httpx`、调通一家 LLM API（DeepSeek/Qwen 即可）并实现流式输出 | 一个 CLI：读入问题 → 流式打印回答 → 带超时、重试、`--debug` 打印 token 用量 |
| W2 | 10/26–11/01 | FastAPI 路由与依赖注入、pytest + fixture + mock LLM、Docker 基础 | 一个 `/chat` 服务：**有 8 条 pytest 用例（含 mock）**，`docker run` 一条命令起得来 |

**验收（M1-a）**：`pytest -q` 全绿；`docker compose up` 后 `curl` 能拿到流式响应；README 写清怎么跑。

**坑**：不要在这里看 20 小时 Python 教程。你会写脚本，缺的是工程约束——直接在项目里补。

### 阶段 1｜RAG（W3–W6，11/02–11/29）

**目标**：从"抄一个 RAG"到"能证明我的 RAG 更好"。

| 周 | 日期 | 主线 | 周末交付 |
|:--|:--|:--|:--|
| W3 | 11/02–11/08 | 文档加载与切分（PDF/Markdown，表格与图片处理）、Embedding 原理、Chroma/FAISS 本地索引 | 能对 50 份 PDF 建索引并按引用回答 |
| W4 | 11/09–11/15 | 检索评估：先建 **30 条评测集**（问题 + 标准答案 + 应命中的 chunk），再改 chunk 策略做对比 | 一张对比表：3 种 chunk 策略的 Recall@5 / MRR |
| W5 | 11/16–11/22 | Advanced RAG：Query 改写（HyDE/Multi-Query）、BM25 + 向量混合检索、Reranker | 混合检索 + rerank 后 Recall@5 相对基线提升 ≥10%（写清数据） |
| W6 | 11/23–11/29 | 生成侧评估（RAGAs：Faithfulness / Answer Relevancy）、Milvus 单机部署、Docker 打包 | 端到端系统 + 评估报告（基线 vs 优化版四指标对比） |

**里程碑 M1**：`rag-service` 仓库——Docker 一键起，30 条评测集可复跑，README 里有一张"优化前后指标表"。

**坑**：90% 的人卡在"没有评测集"就开始调参。W4 必须先建集，再调优。这是你的主场，别浪费。

### 阶段 2｜Agent 核心（W7–W11，11/30–01/03）

**目标**：**先手写，再用框架**。手写过一遍，框架就只是脚手架；反过来，你永远只会调 API。

| 周 | 日期 | 主线 | 周末交付 |
|:--|:--|:--|:--|
| W7 | 11/30–12/06 | 不用任何框架，**手写 Agent Loop**（150 行内）：tool registry（dispatch 表）、最大步数、超时、结构化输出解析 | `mini-agent`：3 个工具（计算器、搜索、读文件）+ 完整消息轨迹打印 |
| W8 | 12/07–12/13 | Function Calling 深入、工具 schema 设计与描述工程、错误重试与降级 | 工具失败率对比实验：无重试 vs 指数退避 vs 降级兜底 |
| W9 | 12/14–12/20 | MCP：写一个自己的 MCP Server（如"本地文档检索"），接进客户端 | 可被任意 MCP 客户端调用的 Server + 契约测试 |
| W10 | 12/21–12/27 | Memory（短期/会话/长期，Mem0 思路）+ **Context Engineering**：分层上下文、压缩触发、检索注入 | 一个能跨会话记住用户偏好的助手 + 压缩前后 token 对比 |
| W11 | 12/28–01/03 | 状态机与编排（LangGraph）：中断、人工确认、恢复；读一个真实 Harness 源码（Claude Code / learn-claude-code / OpenHands） | 研究助手 Agent（RAG + 搜索 + 引用）+ 一页"Harness 拆解笔记" |

**里程碑 M2**：`mini-agent` + `research-agent` 两个仓库；研究助手能对 10 个问题给出带来源的回答，并有 trace 记录。

**坑**：W11 读源码别通读，只找四件事：loop 在哪、tool 怎么注册、权限怎么拦、context 怎么压。找到就停。

## 五、每周怎么用这 10 小时

| 时段 | 时长 | 做什么 | 为什么 |
|:--|:--|:--|:--|
| 周一–周五 | 5 × 1h | **输入**：读文档/看课/读源码，记卡片（每张 ≤ 200 字） | 碎片时间适合吸收，不适合调试 |
| 周六 | 3h | **输出**：写代码，推进本周主线 | 需要连续时间才能进状态 |
| 周日 | 2h | **输出**：交付 + 验收 + 写 5 行周报 | 收尾与复盘，形成闭环 |
| 每月最后一个周日 | 额外 | 复盘 + 发一篇技术文章 + 更新简历 | 公开输出是复利 |

**三条铁律**

1. **输入 : 输出 = 1 : 1**。只看不写的那周，等于没学。
2. **每周至少一次 commit**。仓库连续两周空白，说明计划已经失效。
3. **周报只写五行**：学了什么 / 卡在哪 / 下周怎么改 / 产出链接 / 自评（1–5 分）。

**掉队自救**（比计划本身更重要）

- 断更 ≤ 3 天：直接继续，**不要补课**。补课是弃坑的第一步。
- 断更 > 1 周：把当前周的任务砍一半，先恢复节奏。
- 某周任务卡住 > 2 小时：降级方案（换更简单实现），写进"已知限制"，继续往前。
- 连续两周自评 ≤ 2 分：删掉一个非核心任务，而不是延长时间。

## 六、两个简历项目（怎么做才值钱）

### 项目 1：垂直业务 Agent（证明你能做产品）

**建议选题**：技术文档/工单处理助手（贴合你熟悉的研发流程，数据也好拿）。

| 维度 | 要求 |
|:--|:--|
| 用户与场景 | 明确一个用户角色 + 一个高频任务 + 成功标准（不是"智能问答"） |
| 架构 | Agent Loop + dispatch 表注册 5+ 工具 + 分层上下文 + 高风险操作人工确认 |
| 数据 | 真实文档/工单 100+ 条，自建 30 条评测集 |
| 工程 | 超时/重试/降级、成本上限、trace、Docker 部署、CI |
| 指标 | 任务成功率、平均步数、单次成本、P99 延迟，**四项都要有数字** |

**简历写法（示例）**

> 面向研发工单场景构建垂直 Agent：手写 ReAct loop + dispatch 表注册 6 个工具，四层上下文管理（system/长期/会话/单轮），高风险写操作接入二级人工确认。自建 30 条评测集，端到端成功率 82% → 91%（上下文压缩 + 工具重试策略），单任务成本下降 43%，P99 延迟 3.2s。

### 项目 2：Agent Eval / Replay 平台（证明你稀缺）

**这是你的差异化武器**，也是第六章开头说的"交叉件"。

| 模块 | 说明 |
|:--|:--|
| 用例管理 | YAML 定义任务 + 期望 + 判定方式（精确 / rubric / LLM-judge） |
| 批量执行 | 并发跑、多模型对比、重复 N 次测稳定性 |
| 轨迹回放 | 保存每步 messages / 工具调用 / 耗时 / token，可逐步回看 |
| 失败归因 | 自动分类：工具选错 / 参数错 / 循环 / 幻觉 / 超时 / 上下文溢出 |
| 回归看板 | 版本对比（通过率 diff、成本 diff、延迟 diff），CI 里跑 |
| 报告 | 一键导出 markdown 报告，可直接贴进 PR |

**简历写法（示例）**

> 设计并实现 Agent 评测与回放平台：YAML 用例 + 并发执行 + 轨迹回放 + 自动失败归因（6 类）；支持多模型/多版本对比与 CI 回归。累计 200+ 用例、覆盖 3 个项目，单轮回归从人工 4 小时压缩到 6 分钟，帮助定位 17 个工具调用缺陷。

> 两个项目的分工：项目 1 回答"你会不会做 Agent"，项目 2 回答"为什么该要你而不是别人"。
